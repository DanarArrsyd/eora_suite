## Keys and invariants
- Tenant-aware unique constraints, foreign keys and indexed scope columns. Tenant boundary in all queries, jobs, exports and object-storage paths. Evaluate PostgreSQL RLS as defense in depth but do not rely on it as the only tenant control.
- Quantities as exact decimal/numeric with defined precision; never binary floating point for stock. Units and conversion version required. Integer counts where physically discrete; measured kg/length exact decimal.
- Movement ledger append-only for posted movements; reverse with compensating movement, never edit posted history. Atomic stock balance projection update in same transaction; reconcile projection periodically to ledger.
- Status/ownership/location are distinct dimensions; transfers preserve quantity conservation; issue to Production is a location/custody transfer, not automatic consumption.
- Optimistic versions for documents; locks for stock-critical postings; idempotency keys and unique posting references; outbox inserted in same DB transaction.
- Every genealogy link references actual input/output lot and WO/run/operation; multi-lot and multi-WO allocations supported.
- Date/time: store UTC instants, display tenant timezone; define shift production date and cutoff separately. No silent retrospective posting to closed periods.

## Data products and query models
Operational ledger and OLTP records authoritative. Derived stock projections, daily aggregates and dashboards are rebuildable. Read replicas/reporting store only if measurements justify. Report `as_of`, timezone, freshness, and filter scope.

## Time model (D-044, ADR-0012)
| Concept | Definition | Storage |
|---|---|---|
| Transaction Timestamp | instant the posting is committed (`posted_at`) or the event happened (`occurred_at`) | `timestamptz` (UTC) |
| Plant Timezone | IANA zone of the plant; inherits tenant default (`Asia/Jakarta`) unless overridden | `plants.timezone` |
| Calendar Date | local date of the transaction timestamp in the plant timezone | derived, stored on documents as `calendar_date` for reporting |
| Production Day Cut-off | local time at which a production day starts (e.g. 07:00); configured on the business calendar | `business_calendars.production_day_starts_at` |
| Production Date | date of the production day the event belongs to: local time ≥ cut-off → same calendar date; < cut-off → previous date | `date`, stored on every posting (DD-08) |
| Shift / Shift Date | shift resolved from the shift calendar; shift date = production date of the shift start (a shift 23:00–07:00 starting Mon belongs entirely to Mon's production date) | `shift_id`, `shift_date` |
| Week Start / Week End | ISO 8601: Monday 00:00 → Sunday 24:00 of the **production date** (planning) or **due date** (demand) in plant timezone | derived; bucket key `YYYY-Www` |
| Requirement / Due Date | customer date, daily granularity, plant calendar | `date` |
Rules: never infer production date from `posted_at` alone; backdated postings carry their own production date and are checked against the open period (BR-PER-01); calendars are versioned (`effective_from`) so historical buckets do not move when a plant changes its cut-off. Example: plant cut-off 07:00, shift S3 23:00–07:00 → a posting at Tue 02:30 WIB has calendar date Tue, production date **Mon**, shift S3, ISO week of Mon.

## Inventory ledger posting specification (Phase 3.5; ADR-0002, ADR-0014)
All postings go through `InventoryPostingService` in one DB transaction: validate command → resolve calendar (production date, shift) → check period OPEN → lock affected `stock_balances` rows **in deterministic key order** (`SELECT … FOR UPDATE`, ordered by balance key) → validate `qty + delta ≥ 0` and allocations → insert `inventory_documents` + `inventory_movements` legs (+ `genealogy_edges`) → update projections → insert `outbox_events` + `audit_events` → commit. Idempotency key unique per tenant (replay returns the stored result; same key with a different payload → `409 IDEMPOTENCY_KEY_REUSED`). Bounded retry on `40001`/`40P01`. No external I/O inside the transaction; `SET LOCAL statement_timeout` and `lock_timeout` guard runaway locks.
